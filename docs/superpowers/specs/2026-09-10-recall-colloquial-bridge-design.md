# 口语桥接（Colloquial Bridge）— 设计（方向 5 重定位）

> 日期：2026-09-10  
> 状态：**待审阅**  
> 作者：DSH reviewer（依据 v2 评测给出的靶区 + 本次可行性实测）  
> 相关：[`reports/2026-09-10-recall-eval-v2-g-verdict.md`](../reports/2026-09-10-recall-eval-v2-g-verdict.md)（T3 停用裁定）· [`reports/2026-09-10-recall-p0-g-verdict.md`](../reports/2026-09-10-recall-p0-g-verdict.md)  
> v2 基线（门禁已生效）：Acc@1 **0.600** · Recall@5 0.725 · MRR@5 0.653 · nDCG@5 0.667 · 拒答 **0.382**；分层 A **1.00** / B 0.400 / C 0.900 / D 0.900 / **E 0.100**

## 0. 可行性前置（reviewer 实测，决定了本设计的方向）

在动笔前先验证「方向 5 = 混合检索」是否可做：

| 检查 | 实测 | 结论 |
|---|---|---|
| 仓库是否已有 BM25 / 倒排 / TF-IDF | 全仓 grep **零命中** | 需自研（可零依赖实现） |
| 仓库是否已有 embedding 计算/消费 | `special_element` 表有 `embeddingJson/embeddingStatus/embeddingModel/embeddingContentHash` 与 pending/ready/stale 生命周期，但**全仓无任何向量计算、无 /embeddings 调用、无向量检索** | **只有 schema，没有实现**——embedding 路线属净新增基础设施 |
| 依赖 | `exceljs, express, knex, minio, multer, mysql2, playwright, pngjs, undici, ws` | 无任何 ML/向量库 |
| 延迟预算 | 现召回热态 **p95 0.14ms**；embedding 需每次查询走网络（LLM 网关 `LLM_BASE_URL`） | 延迟抬升 **3 个数量级**，且 propose 是逐原子调用 |
| **E 层性质** | 50 条**纯口语改写、不出现卡面原词**（如「把客户的口子先封住不让他接着支取」） | **BM25 原理上无效**——它依赖词面重叠 |

**结论：直接做「混合检索」无法命中真正的靶区。** 本设计据此重定位：

- **主路径 = 口语桥接**（领域语料建表；零依赖、可审计、可回退）——它才是打 E 层的正解；
- **BM25 降级为后续低风险增量**（收益在长查询与 C/A/D 的词面变体，**对 E 层无效**）；
- **embedding 升格为独立基础设施立项**（需 Lead 决策：端点是否提供 /embeddings、模型选型、向量存储、离线降级、延迟预算）。

## 1. 目标

修 v2 照出来的两个靶区，**零依赖**：

1. **E 层**：Acc@1 由 **0.100** 提升到 **≥0.25**（同一批 50 条口语条目）；
2. **近域负样本 FPR**（当前 **0.92**，25 条中 23 条误命中）：**不恶化**（≥0.92 保持），拒答率 **≥0.382** 不降；
3. **不得回退**：A 层 ≥0.95（现 1.00）、B/C/D 不低于基线、**零新增 FP**；
4. 桥接资产**可独立辩护**：每条 `term → expand` 有可追溯来源，**不得标注「失败反推」**；
5. 若达标 → 才接线 `propose.js`（含 `moduleKey` scope 门控）；不达标 → 资产归档、**不计成果**。

## 2. 范围

### In
- 新资产 `data/kb/colloquial-bridge.json`（口语↔领域词桥接表，v1）。
- 建表 SOP（三类素材 + 双向校验 + 人工裁决）。
- 在 **v2 的 E 层 + v2-new B 层**上做独立增量度量。
- 达标后接线 `propose.js`（仅注入参数，不改既有语义）。

### Out
- **不做 BM25 / 不做 embedding**（理由见 §0；embedding 另立项）。
- 不改召回算法主逻辑（沿用 T3 已落地的 opt-in 扩展机制 `applySynonymExpansion`）。
- 不改评测集、门禁、阈值（floor 只升不降）。
- 不复活 `data/kb/synonyms.json`（它 `status: unvalidated`，作为**反例素材**保留）。

## 3. 现状与靶区（v2 实测）

| 靶区 | 指标 | 说明 |
|---|---|---|
| E 层口语改写 | Acc@1 **0.100**（5/50） | 无卡面词的业务口语；现机制只能靠 CJK bigram 偶然命中 |
| 近域负样本 | FPR **0.92**（23/25 误命中） | 与业务语料天然重叠的领域词（还款/授信/贷款） |
| T3 反例 | 泛化 **1/115** | 失败反推的表只对建表集本人有效（记忆） |

## 4. 设计决策

| # | 决策 | 理由 | 备选 |
|---|---|---|---|
| **D1** | 桥接表**只从领域语料建**，禁止失败反推 | T3 用失败反推 → 1/115 泛化，被判停用；语料建表天然不依赖评测样本 | 继续失败反推（已被证伪） |
| **D2** | 素材三类：**A 卡面同义**（84 卡 `aliases/keywords` 内部已有的同义表述）· **B 需求语料**（`chapters/`、`through-chains.md` 中的业务口语）· **C 湿测 drift 记录**（`wet-test.md` 里 wording 类「文档词 vs SUT 词」正是现成的措辞桥） | 三类均在仓库内、均不依赖评测失败；C 尤其独特：drift 回流本就记录了「文档『提交流程』vs SUT『流程提交』」这类真实措辞差 | 只靠人工拍脑袋（不可审计） |
| **D3** | 新文件 `data/kb/colloquial-bridge.json`，与旧表物理分离 | 旧表已被判 `unvalidated`；混用会让"分歧来源"不可归因 | 版本化旧文件（血缘混乱） |
| **D4** | 每条必须写 `source`：`corpus-card` / `corpus-req-doc` / `wet-test-drift` + 具体文件与行/叶号 | 可审计、可回滚、可人工抽检 | 无来源（等同不可辩护） |
| **D5** | 沿用 T3 机制（opt-in、`SYNONYM_WEIGHT`、`scope` 门控），**不改算法** | 机制已在 v2 上验证为"无害"（零新增 FP、A 层不动） | 重写检索（风险大） |
| **D6** | 验收只看 **v2 全新地面**（E 层 50 + v2-new B 层 15），**不看 v1 携带条目** | 携带条目是"旧集"，看它们等于自我复读（T3 教训） | 看聚合（会被记忆项污染） |
| **D7** | 达标才接线；接线必须带 `moduleKey`（scope 门控） | 全表 `scope=null` 会全局生效，影响面远超评测集 | 先接线再验证（不可接受） |

## 5. 建表 SOP（可机械执行）

1. **候选生成**：脚本从三类素材抽取候选对
   - A：同一卡内 `aliases/keywords/flow` 之间的**非同形近义**（如 alias「对私用信申请修改查看」↔ keyword「流程轨迹」）
   - B：`chapters/` 与 `through-chains.md` 中小括号内的替代说法、并列词（「禁用/下架」「上移/下移」）
   - C：`wet-test.md` 的 wording 类 drift 行，按「文档口径 vs SUT 实测」成对抽取
2. **双向校验**：候选必须满足「`term` 在真实 query 侧可能出现」且「`expand` 能在目标卡面命中」——用**语料 grep** 验证，**禁止跑匹配器**。
3. **人工裁决**：逐条判可辩护性，剔除过泛/歧义；每条留 `source` 与裁决理由。
4. **规模**：v1 目标 **40–80 条**（不是越多越好；每条都要能辩护）。

## 6. 数据模型（`data/kb/colloquial-bridge.json`）

```json
{
  "bridgeVersion": "v1",
  "status": "candidate",
  "builtFrom": ["corpus-card", "corpus-req-doc", "wet-test-drift"],
  "buildDiscipline": "禁止使用 kb-recall-eval.* 的任何失败条目作为建表依据",
  "entries": [
    { "term": "口子封住", "expand": ["冻结"], "scope": "limit", "source": "wet-test-drift credit-corp 叶12 wording" }
  ]
}
```

## 7. 验收

| 项 | 判据 |
|---|---|
| E 层 | Acc@1 **≥0.25**（现 0.100 / 50 条） |
| 全新地面独立增量 | **≥4 条**（E 层 + v2-new B 层）——避开 v1 携带条目 |
| 不回退 | A ≥0.95（现 1.00）；B ≥0.400；C ≥0.900；D ≥0.900 |
| 精确性 | 拒答率 **≥0.382**；**零新增 FP**（34 FP 集合不变） |
| 门禁 | `characterize-kb-recall-eval` 5 passed；`--baseline` exit 0 |
| 可辩护 | reviewer 抽检 10 条桥接条目，核 `source` 真实性与合理性 |
| 接线（仅当全过） | `propose.js` 只新增参数注入；行为在未传桥接表时字节不变 |

## 8. 测试策略
- pin：桥接机制沿用既有 3 条 pin（已在 `characterize-flow-card-recall`），新增**桥接表加载/scope 门控/空表不变**三条。
- **建表隔离**：建表期**不得**读 v2 的任何条目（含失败清单）——沿用既有隔离纪律，G2 专查。
- 度量只跑 v2（E 层单独报 + 全新地面增量单独报）。

## 9. 风险

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 桥接表条目过泛 → 新增 FP | 双向校验 + 拒答率硬门 + 抽检 |
| R2 | 又变成"对评测集的记忆" | D6：只看全新地面增量；建表禁读评测失败 |
| R3 | E 层口语无穷无尽，40–80 条覆盖不足 | 明确 v1 只求"可辩护的起点"，E 层目标 0.25 不是 1.0 |
| R4 | 接线后影响面扩大 | D7 + 未达标不接线 |
