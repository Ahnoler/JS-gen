# 报文捞取 + 日志解析：非消费型历史数据可用于表单字段回填（验证说明）

> 对象：信贷系统开发人员
> 日期：2026-08-26
> 验证环境：dev 开发环境（test.creditv5p2.tansun.com.cn），拦截器日志经 ELK 采集

## 一句话结论

拦截器日志（DemoHeadIntercept 产出）中的历史 API 报文，可以被完整捞取、解析并映射到表单字段，用于空表单回填——非消费型历史数据（客户名称、地址、证件号、各类下拉码值等）可直接复用；仅识别为消费型（验证码/一次性 token）与系统审计字段需排除。

## 验证链路

    ELK 日志（appName=tansun-tcp-cst）
      → 报文捞取：按时间窗/接口筛选，3 天 2186 条完整报文，解析 0 失败
      → 接口归属：每条报文带 uri + method（如 /custCorporat/saveCustCorporat POST），
        与页面元素定义（接口一）的网关 url 做段级后缀匹配自动对应
      → 字段映射：报文 requestBody 字段名 与 表单元素 prop 一一对应（纯字段名结构匹配，非值匹配）
      → 回填：空表单 29 个字段成功填入（文本/日期/金额/下拉），金额自动格式化正常

## 码值说明（对信贷开发人员重要）

1. 日志报文中下拉/枚举字段为**码值**（如 diffplcCstInd=0、hldgEcnTp=B0102、oprtSt=01），页面展示为中文；
2. **码值→文案 转换由 JS-gen 自页面选项采集解决，无需信贷系统提供转换表**（页面下拉选项的组件结构自带码值绑定，已实测）；
3. 若后续提供统一字典接口亦可降低采集成本——非必需。

## 需要信贷系统开发人员做的

1. **接口一（P0）**：GET /api/element-definitions?pageUrl=页面路由 → 返回该页面所有表单元素 {name(中文名), prop(API字段名), url(所属接口)}；
2. **接口二（P1）**：GET /api/interface-structure?url= → {method, inputParams[字段名]}；
3. **接口三（P0）**：GET /api/app-log?appName=&from=&to= → 返回应用日志文本（拦截器已集成，只需开放日志读取；**当前 JS-gen 从 ELK 获取等价的日志数据**）；
4. **字段名一致性**：接口一 prop = 接口二 inputParams = 日志 requestBody key，三者必须同名。

## 认证 / 安全 / 数据说明

- 三个接口均为 GET 只读，复用现有 token 认证；
- 日志中敏感字段已脱敏（如 913301****7XW8T3R），回填时 JS-gen 标注「待人工校正」或按规则生成合法测试值；
- 数据不会写回被测系统，仅用于验证与字段映射。
