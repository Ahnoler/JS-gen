# 评测集 v2 — 设计（扩版 + 独立标注 + 门禁切换 + T3 重评协议）

> 日期：2026-09-10  
> 状态：**待审阅**（批准后进入 `plans/2026-09-10-recall-eval-v2.md`）  
> 作者：DSH reviewer（依据 recall P0 三杠杆 G3 结论 + 基于公开标准的重评分）  
> 相关：`reports/2026-09-10-recall-p0-g-verdict.md`（T3 停用裁决）· `specs/2026-09-09-kb-recall-eval-design.md`（v1 设计与 D1–D11）  
> 现行生产基线（T2 链态）：**Acc@1 0.740 · Recall@5 0.847 · MRR@5 0.784 · nDCG@5 0.798 · 拒答 0.633**；分层 **A 1.00 / B 0.233 / C 0.867 / D 0.933**

## 1. 目标

把召回评测从「130 条、含自证条目、B 层仅 30 条」升级为**大样本、全独立、能判别口语/同义改写**的常态门禁，并给 T3（受控词表）一个**干净的泛化检验**。

成功终点（可机械验证）：

1. **v2 规模：目标 245、底线 ≥235**（v1 的 130 条**原样保留** + **新增 ≥105 条全独立查询**），正样本 ≥180、**负样本 ≥55**；
2. **新增层 E（口语/同义改写）≥ 50 条** —— 这是 B 层主战场，样本量决定判别力；
3. 正样本覆盖 **≥ 70 张不同卡**，单卡 ≤ 4 条；query 无重复；无陈旧 gold；
4. **标注独立性**：标注过程**不得**运行匹配器；reviewer 抽检 15 条，分歧率 **≤ 10%**；
5. **门禁切到 v2**，阈值**重测后由 Lead 批准**（不继承 v1 floor）；切换后 `--baseline` 对新基线 **exit 0**；
6. **T3 重评协议落地**：词表一律用**旧的 v1 失败集**建、在**全新的 v2** 上验证泛化 —— 出**独立正增量**才算通过。

## 2. 范围

### In

- `scripts/characterization/fixtures/kb-recall-eval.v2.json`（新冻结集）。
- v1 自证条目的**重标**（独立标注替换），并在 v2 的 `changeLog` 逐条记录。
- 门禁切换到 v2 + **基线重测** + **阈值提案**（Lead 批）。
- 分层指标入门禁（吸收上一轮遗留：A 层独立下限）。
- **T3 重评协议**（v1 建表 → v2 验证），作为 v2 的第一个消费者与验收演示。

### Out（不做）

- 任何召回算法改动（方向 5 混合检索**排在 v2 之后**：BM25 修不了口语同义词，embedding 需引依赖且需 v2 才能判别收益）。
- **不接线** `propose.js`（T3 未过泛化前不接线，见 G3 裁决）。
- 不改 v1 文件本身（归档保留，保证历史基线可复现）。
- 不引依赖。

## 3. 现状与问题（v1 的四个硬伤）

| # | 问题 | 证据 |
|---|---|---|
| P1 | **样本小、判别力弱** | 100 正样本，Acc@1 的 Wilson 95% CI = **[0.553, 0.736]**（宽 0.18）；B 层仅 30 条，±1 条 ≈ ±0.033 |
| P2 | ~~存在自证条目~~ **（reviewer 更正）** | **该条不成立**：v1 的 20 正 + 10 负来自 reviewer 的独立 hold-out，其余 100 条为实施方标注，**reviewer G1 盲判抽检 11/11 一致**。「16 条以实现输出为期望」是**契约金样例** `kb-recall-golden.json`（24 条）的问题，**不是** 130 条评测集；金样例属跨语言契约，不在 v2 范围内 |
| P3 | **口语/同义层薄** | B 层 30 条要同时承担「判别词表/混合检索」两类改动的证据职责，**不足** |
| P4 | **建表集与验证集同源** | P0/T3 用 v1 的 35 条失败五五分离建/验 → 建表集仅 18 条，任何失败反推的词表都无法证明泛化（实测 verify 独立增量 = 0） |

## 4. 设计决策

| # | 决策 | 理由 | 备选 |
|---|---|---|---|
| **D1** | **v2 = v1 的 130 条原样保留（gold 一字不改）+ 新增 ≥100 条全独立** | v1 标注已经 G1 抽检（11/11）与结构核验，**无证据支持重标**；擅改会破坏历史基线可比性。新增条目走 `source: "v2-new"` | 全新建（历史不可比）／批量重标（无依据且破坏可比性） |
| **D2** | 新增 **E 层（口语/同义改写）≥50 条** | B 层是主战场，且是 T3/方向 5 的共同靶区 | 只扩 A/B/C/D（判别力提升有限） |
| **D3** | 标注纪律沿用 v1：**禁跑匹配器** + 多 gold + 歧义进 `excluded` + 双人复核 + reviewer 抽检 15 条 | 已证明有效（v1 G1 15/15） | 单人标注（独立性无保障） |
| **D4** | **建表集与验证集物理分离**：词表/别名等资产用 **v1 失败集**建，**只在 v2 上验**（v2 不参与任何建表） | 这是 T3 失败的根因修复；旧集建表、新集验证才是干净泛化检验 | 继续在同一集内五五分离（P4 已证明不可行） |
| **D5** | 门禁切 v2 后，**阈值必须重测后由 Lead 批准**，**不继承** v1 floor | v2 分布不同（加了 E 层），继承 floor 会失真 | 直接继承（会产出无意义的红/绿） |
| **D6** | v1 文件**归档保留**、v2 新文件、`--fixture` 可切换 | 历史基线可复现；迁移期可对跑 | 原地改 v1（破坏冻结与可比性） |
| **D7** | 分层指标**入门禁**：除六项聚合外，加 **A 层下限 ≥0.95** | P0 的教训：A 层零容错，是最灵敏的检索回归探测器；B/D 已成主战场 | 只报不卡（回归无护栏） |
| **D8** | 不引依赖、不改算法 | 本版是**数据与门禁**工程 | — |

## 5. 数据模型（`kb-recall-eval.v2.json`）

```json
{
  "evalVersion": "v2",
  "frozenAt": "...",
  "labelers": ["..."],
  "reviewers": ["..."],
  "changeLog": [
    { "at": "...", "by": "...", "why": "v2 创建：v1 全量保留 + 新增 N 条独立；重标 M 条自证项", "approvedBy": "Lead" }
  ],
  "carriedFromV1": 130,
  "relabels": [],
  "relabelsNote": "例外通道：仅当标注新增条目时**发现** v1 某条明显错误才启用，须逐条写 why 并经 reviewer 复核；默认必须为空数组",
  "source": "v1",
  "relabeledFixture": "scripts/characterization/fixtures/kb-recall-golden.json（24 条，属跨语言契约，不在 v2 范围）",
  "entries": [
    { "id": "A-001", "tier": "A", "query": "...", "gold": ["..."], "source": "v1" },
    { "id": "E-001", "tier": "E", "query": "...", "gold": ["..."], "source": "v2-new", "note": "口语改写，不出现卡面原词" }
  ],
  "excluded": [ { "query": "...", "why": "歧义" } ]
}
```

- 层定义：A 词面一致 / B 改写同义 / C 场景长句 / D 别名短码 / **E 口语改写（v2 新增）** / N 负样本。
- **N 层同步扩到 ≥50**：跨域无关 30 + **近域无关 20**（后者是 FP 的主要来源，T3 遗留的 N-002 即此类）。

## 6. 度量口径

- **沿用 v1 全部口径**（multi-gold 分数化 `hits/|gold|`、`DCG/IDCG`、冷热延迟分报、噪声 Δ）。
- **新增**：`byTier` 全层输出 + **A 层下限断言**（D7）。
- 阈值只升不降；改口径 = 改基线 = 须 Lead 批准（承接条件不变）。

## 7. 验收

| 项 | 判据 |
|---|---|
| 规模 | 条目 ≥230（正 ≥180 / 负 ≥50）；E 层 ≥50 |
| 覆盖 | 正样本覆盖 ≥70 卡；单卡 ≤4；query 无重复；无陈旧 gold |
| 层配额 | E ≥50 且三子模式各 ≥15（带 `pattern`）；N ≥55（跨域 30 + **近域 25**）；A≥55 / B≥45 / C≥20 / D≥20 |
| 标注独立性 | reviewer 抽检 15 条（重心在新标部分，不含任何 v1 种子）→ 分歧 ≤10% |
| 例外重标 | `relabels` **默认为空**；若非空，逐条有理由且经 reviewer 复核 |
| v1 保真 | v1 的 130 条 id/query/gold/tier 与 `kb-recall-eval.v1.json` **逐字段一致**（机械 diff，允许 0 差异） |
| 门禁 | `characterize-kb-recall-eval` 读 v2；`--baseline` 对新基线 exit 0；**阈值 +0.2 仍必红**（证伪性保持） |
| T3 重评 | 词表（v1 失败建）在 **v2 上测出独立正增量**；否则 T3 维持停用 |

## 8. 测试策略

- 评测集是**数据**：只做结构校验（条数/分层/覆盖/无重复/gold 存在），不做源码 pin。
- **建表隔离**：词表构建期**物理隔离** v2（不得读 v2 的条目）——沿用 P0/T3 的做法（把验证集从上下文排除）。
- **对跑**：切换后保留 `--fixture v1` 能力，确认 v1 旧数字仍可复现（历史可比）。

## 9. 风险

| # | 风险 | 缓解 |
|---|---|---|
| R1 | 标注质量随规模下降 | 沿用双人复核 + reviewer 抽检；歧义一律剔除；宁可少不可脏 |
| R2 | v1/v2 分布漂移导致分数变化是假象 | 切换时**重测基线**、不继承 floor；报告须给 v1/v2 对跑表 |
| R3 | 建表时误读 v2（污染） | D4 物理隔离 + 构建脚本只接受 v1 失败集路径 |
| R4 | 成本（230 条标注） | 分层配额先行落盘；可分子智能体并行（各自独立标注，防串味） |
| R5 | 切换期门禁红灯误判 | 用独立 commit 切门禁；切换前先出对跑表 |

## 10. 决策确认（2026-09-10 已定）

Lead 裁定：**全部按 reviewer 推荐执行**。

| # | 决策项 | 采纳结论 |
|---|---|---|
| 1 | **D1 v2 构成** | **v1 的 130 条原样保留（gold 一字不改，机械 diff 0 差异）+ 新增 ≥105 条全独立**；`relabels` 仅作例外通道、默认空 |
| 2 | **E 层配额** | **≥50 条，且三子模式各 ≥15**（`colloquial-synonym` / `colloquial-verb` / `colloquial-domain`），每条带 `pattern` 字段；**子模式分层优先于单纯加量** |

| 6 | **D5 阈值** | **先测后定、不继承 v1 floor**；v1/v2 对跑表先出，阈值提案经 Lead 批准后写入 |

实施按 plan T0 → T6 推进；建表隔离（构建期不得读 v2）是本次纪律命门，reviewer 在 G2 专查。
