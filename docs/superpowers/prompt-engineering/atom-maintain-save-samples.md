# 详情页维护/保存样例：对齐 #708，禁止排序+保存混写

这些例子说明**详情页维护/保存**怎么写成可独立录制的 atom。金形来自产品库湿测 **#708**（产品树搜索/定位并选中未启用产品 → 右栏基本信息页签 → 编辑 →【保存】），规则本身通用：维护已有对象前必须在本笔内定位并选中它，并用 `dataDependsOn` / 「关键数据」点名该对象。

**不是**「产品树每一层必须拆」教条；也不把树排序（上移/下移）写进维护保存。

## 正例：对齐 #708 · 选中产品 → 基本信息 → 保存

本笔不新建产品；开录前「产品」须已存在（上游 atom `produces`，或 `source: "preset"`）。`taskDraft` 自带搜索/定位/选中，不假设同链前序步骤已把节点点亮。

```
produces: []
dataDependsOn: ["产品"]

taskDraft:
1、进入功能页，等待加载
2、搜索/定位并选中已有未启用「产品」
3、右侧打开基本信息页签
4、维护必填字段
5、【保存】

关键数据
产品：KB测产品
```

要点：

1. 进页（若需要）→ 搜索/定位 + 选中 → 打开相关页签 → 编辑 → 一次保存。
2. 「关键数据」与 `dataDependsOn` 键名一致，写明**正在维护哪条产品**。
3. 同层排序（上移/下移）不出现在本笔。

## 反例：同层排序 + 维护基本信息【保存】

把树排序能力当作维护保存的前序，是 wet propose 后 `product-mgmt:chain-a:6` 的误合并。

```
# 不要这样
produces: []
dataDependsOn: []

taskDraft:
1、同层排序（与相邻节点互换序号），操作：【上移】/【下移】
2、（可选）维护基本信息 →【保存】
```

问题：

1. 上移/下移是**独立可录能力**（校验产品树同层序号），与基本信息落库无关。
2. 拆成独立 atom 后，维护笔不再继承「链上前序已选中某节点」的隐含上下文，必须自己写搜索/定位/选中，并点名 `dataDependsOn`。
3. 排序若保留：单独一笔（选中节点 →【上移】或【下移】）；不写进维护保存。也可省略排序，不进草稿集。

硬闸：`mixesSortWithBasicInfoSave` 为真时 materialize 拒收 `unrelated_capability_merge`，混合稿不会发出。
