## 主链1：信审会全流程（安排会议 → 投票 → 汇总 → 主任审核 → 最终有权人审批）
- 闭环目标：一笔对公授信申请经信审会审议后形成最终批复（通过/否决），更新流程状态并生成批复/呈批表。
- 前置条件：授信/评级/用信/贷后审批流程按规则触发信审会；机构已配置信审会主任/副主任/普通委员/必参会委员角色与风险评价员；信审会委员人数 5-9 人。
- 有序步骤：
  1. 信审会办公室主任：待办列表 → 授信管理 → 【审批】进入安排会议（基本信息-影像信息-安排会议）【chapters/04；源 3.2.2.1】
  2. 选择抽签模式（自主/随机）→【抽签】/手工勾选参会人员 → 填会议记录人、列席人员 →【保存】（2/3 人数、主任1人、必参会缺席原因等校验）【chapters/03、04；源 3.2.1.1、3.2.2.1.5.3】
  3. 【下一步】→【意见】填写意见详情 →【流程提交】：向参会委员发待办、向记录人发会议记录待办；触发会议纪要流程（状态"待发起"）【chapters/04；源 3.2.2.1.5.4】
  4. 各参会委员：待办任务 → "对公授信信审会会签"页面 → 填意见结论（同意/不同意/续议）+意见详情 →【流程提交】；全员完成后生成办公室主任"汇总委员意见"待办【chapters/05；源 3.2.2.2】
  5. 办公室主任：汇总意见（系统按 2/3+主任意见规则自动决议）→ 结论同意/不同意时选信审会主任提交；结论续议时选择是否重开（≤1次）或退回补充资料/退回第一步【chapters/06；源 3.2.2.3、3.2.1.3】
  6. 信审会主任：审核投票结果 → 结论"同意"选最终有权审批人提交；结论"不同意"确认后流程结束（流程状态"否决"、批复"失效/否决"、生成呈批表）【chapters/07；源 3.2.2.4】
  7. 最终有权审批人：批复意见=同意 → 流程状态"通过"、授信状态"生效"、批复结论"同意"、生成额度台账；=不同意 → 流程状态"否决"；流程结束自动生成"授信审批表"并上传影像【chapters/08；源 3.2.2.5】
- 旁路：
  - 续议 → 重开会议（一次）：重新走步骤1-4，重开时"续议"不可选【chapters/03、06；源 3.2.1.3】
  - 续议 → 退回补充资料：客户经理补充资料后回到办公室主任复核【chapters/03、06】
  - 退回第一步：流程状态"打回"【chapters/06】
  - 主任临时转授权给副主任（备注"代角色名+人名"，副主任获得一票否决权并代理主持）【chapters/03；源 3.2.1.1】

## 主链2：会议纪要线上审批（记录 → 办公室主任审核 → 主任签字 → 存档）
- 闭环目标：会议纪要经记录、审定、签字后状态"通过"并存入档案。
- 前置条件：主链1步骤3已提交（生成记录人待办，纪要状态"待发起"）；记录人必须先点开"汇总委员意见"界面，否则无法提交（提示"未获取到投票结果，无法提交！"）。
- 有序步骤：
  1. 会议记录人：待办列表 →【会议记录】→ 填写会议纪要（会议编号自动生成 HYBH+8位日期+6位顺序号、地点、发言要点≤500字符等）→【保存】【chapters/09；源 3.3.1】
  2. 【下一步】填审批意见 →【流程提交】选信审会办公室主任 → 纪要状态"审批中"【chapters/09；源 3.3.1.5.2】
  3. 办公室主任：待办审定 → "下一步"选联社信审会主任提交；或"退回第一步"打回记录人（状态"打回"）【chapters/09；源 3.3.2】
  4. 信审会主任：签字 →"下一步"确认"会议纪要审核流程即将结束，是否继续" → 纪要状态"通过"；或"退回第一步"打回【chapters/09；源 3.3.3】
- 旁路：记录人【流程撤销】撤销纪要流程【chapters/09；源 3.3.1 业务要素】。
- 待湿测：存入档案依赖档案管理分册。

## 主链3：审查任务池任务分发闭环（分派 → 收回/强制收回 → 重分派）
- 闭环目标：任务池中待办审批任务被正确分派到岗，并支持分派后的收回与重分派。
- 前置条件：授信/用信审查通过生成待办审批任务进入任务池；操作人具备分发权限。
- 有序步骤：
  1. 查看任务池列表（三页签：全部/未分派/已分派，时间倒序；按客户名称/编号/申请流水号/任务状态模糊查询）【chapters/10；源 4.2.1】
  2. 对"未分派"任务【任务分配】（单笔/批量）→ 分配页面选一个/多个用户 →【确认】→ 状态"已分派"【chapters/10；源 4.2.2】
  3. （可选旁路）【收回】：下一岗未点"处理"前收回，二次确认后状态回"未分派"；下一岗已处理则提示"下一岗任务已处理，无法收回"【chapters/10；源 4.2.3】
  4. （可选旁路）【强制收回】：被分配人未提交下一岗前强制收回（二次确认），重分派给他人时系统自动删除已录入授信方案信息；已提交则提示"下一岗任务已提交，无法强制收回"【chapters/10；源 4.2.4】
- 旁路：
  - 【退回】（仅未分派任务）：退回上一节点，二次确认后任务从任务池删除【chapters/10；源 4.2.5】
  - 【详情查看】：按功能跳转详情页【chapters/10；源 4.2.6】
- 闭环边界：任务被分派后的实际审批属授信/用信审查流程（他册），本模块主链到"分派/收回/退回"为止。
