# through-chains · 额度-管控接口（limit-ctrl-api）

> 视图2：候选可贯通主链清单。源：D03天阳信贷管理系统-额度管理需求分册【管控接口】。
> 本册为**纯接口分册**（无界面、无操作步骤），主链以「接口调用序列闭环」定义：每条链可由外部系统按序调接口完成一个业务闭环，可用 API 湿测验证。

## 主链 1：额度占用 → 释放 → 冲正（合同实占闭环）
- **闭环目标**：一笔合同占用额度后全额释放回退；冲正路径可撤销占用。
- **有序步骤**：
  1. `额度创建`（1.1.1）登记额度（节点列表，状态默认生效）
  2. `额度占用`（1.1.3）按合同金额实占（生成占用流水）
  3. `额度释放`（1.1.4）按合同编号释放（≤占用金额）
  4. `额度冲正`（1.1.5）按原业务流水号冲正（仅占用未释放部分可冲）
- **前置条件**：额度生效且未到期；额度归属客户正确；同一合同编号只能占用一次。
- **章节出处**：chapters/01、03、04、05。
- **建议挂载**：额度域叶子接口组（额度管理 functionId），湿测优先级 **高**（核心记账公式链）。

## 主链 2：预占用 → 转实占（预占生命周期闭环）
- **闭环目标**：预占额度后转正式实占，剩余预占按标志释放恢复。
- **有序步骤**：
  1. `额度创建`（1.1.1）
  2. `额度预占用`（1.1.6）生成预占用流水
  3. `额度预占转实占`（1.1.7）按预占用流水号转实占（≤剩余可转实占金额；释放剩余额度标志=是时恢复剩余预占）
  4. （回退）`额度冲正`（1.1.5）
- **前置条件**：额度生效未到期；转实占多占客户列表须与预占用一致。
- **章节出处**：chapters/01、06、07、05。
- **建议挂载**：同主链 1 的额度接口组；湿测优先级 **高**（预占/实占金额口径需验证，见 06/07 章待湿测）。

## 主链 3：限额占用 → 释放 → 冲正（限额闭环）
- **闭环目标**：业务对象占用限额后释放回退、可冲正。
- **有序步骤**：
  1. `限额占用校验`（1.1.13，可选试算，不改数据）
  2. `限额占用`（1.1.14）按维度命中限额逐个占用
  3. `限额释放`（1.1.15）按业务对象编号逐限额释放
  4. `限额冲正`（1.1.16）冲正占用/释放流水
  5. （变体）`限额重算`（1.1.17）恢复原占用后按新维度重命中
- **前置条件**：限额已定义（依赖 D02 限额管理/M01 智能控制配置）；同一业务对象编号不能重复占用；同一交易流水号不能重复释放。
- **章节出处**：chapters/13、14、15、16、17。
- **建议挂载**：限额接口组；湿测优先级 **中高**（与 D02 分册联动）。

## 主链 4：授用一体（注册并占用一步闭环）
- **闭环目标**：一次调用完成额度登记 + 实占（含校验模式试算与失败回滚）。
- **有序步骤**：
  1. `额度注册并占用`（1.1.12）校验标志=是：建临时额度→逐笔占用校验→返回汇总校验结果；校验标志=否：正式登记额度→逐笔实占；任一失败回滚
  2. （后续）`额度释放`（1.1.4）/ `额度冲正`（1.1.5）
- **前置条件**：节点存在；创建机构/创建人员必传；默认不允许超额占用。
- **章节出处**：chapters/12、01、03、04、05。
- **建议挂载**：额度接口组；湿测优先级 **高**（校验/正式双模式 + 回滚语义）。

## 主链 5：额度建立 → 查询核对（只读闭环）
- **闭环目标**：建立额度后通过查询接口核对落账数据。
- **有序步骤**：
  1. `额度创建`（1.1.1）
  2. `额度查询（单笔）`（1.1.9）按额度编号查主表
  3. `额度列表查询`（1.1.10）按客户/额度编号分页核对
  4. `节点列表查询`（1.1.11）核对节点属性
- **前置条件**：查询入参满足必填组合（单笔必传额度编号；列表三选一）。
- **章节出处**：chapters/01、09、10、11。
- **建议挂载**：查询接口组；湿测优先级 **中**（常用作其他链的断言手段）。

## 旁路 / Out
- `集团成员关系同步`（1.1.8）：加入/退出均幂等忽略重复，**不构成独立闭环**，作为主链 1/2 的辅助前置（集团额度场景）。
- `额度占用校验`（1.1.2）/ `限额占用校验`（1.1.13）：纯试算不改数据，为主链 1/3 的前置旁路。
- `附件`（2）：无正文。
- **本册不含**：额度台账 UI 页面、限额定义维护（在 D02 限额管理分册）、审批流。
