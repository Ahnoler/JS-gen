# 草稿交易质量标准（taskDraft 金样）

> 由编排者评审沉淀提炼；跨模块通用。本文件 + 同目录正/反例即全部标准，无需另读仓库其它文档。

## 0. 总原则

**propose 闸门通过 ≠ 质量达标。**

闸门（能力内聚、多次落库、出处、依赖图等）只挡硬违规。  
`present_pick_list` 必须再做质量分拣：仅「较接近金样」→ 建议勾选；薄稿 → 建议暂缓并打标签。

目标：可独立录制的组件级草稿 = 进页 →（定位依赖）→ 一项能力 → 一次落库/查询断言。

---

## 1. 金样五条（建议勾选须同时满足）

| # | 标准 | 合格信号 | 不合格信号 |
|---|------|----------|------------|
| G1 | **进页 / 定位** | 「进入…主页/页面，等待加载」；有 `dataDependsOn` 则须搜索/定位/选中 | 无进页；或第 1 步 `【菜单】→【…】` |
| G2 | **单一业务能力** | 只做新增/维护/删除/查询/设置之一 | 一步 OR 多种写能力；同稿多项可独立验收能力 |
| G3 | **可执行步骤 + 断言收尾** | 末步【保存】/【确定】成功，或「列表展示…」 | 无断言；仅按钮名罗列 |
| G4 | **多步编号，非单行跟表** | `1、2、3…` 分步写动作 | 单行「标题（页面），操作：【A】/【B】」 |
| G5 | **业务名 produces / depends** | 业务对象名（如「产品阶段关系」） | `…产物`；或与 title 雷同占位 |

出处行与关键数据 KV 对齐 produces/depends：金样通常具备。G5 看 produces 字段本身是否业务名。

## 2. 正向骨架（密度跟输入；禁止编造未出现的控件）

### 维护

```
1、进入…主页，等待加载（ZJJK…若有）
2、搜索/定位并选中已有「<依赖>」
3、维护/设置本能力字段（或【设置…】进弹窗）
4、【保存】/【确定】成功

来源：… / …
关键数据
<依赖键>：…
<produces键>：…
```

### 查询

```
1、进入查询…主页，等待加载
2、填写查询条件（已有字段名）
3、点击【查询】
4、列表展示符合条件的记录
```

### 新建

```
1、进入功能页，等待加载
2、（若有依赖）定位并选中上游
3、打开新建入口，填写字段
4、【确定】保存成功
```

禁止系统菜单面包屑写入 taskDraft。

完整正向样例见同目录 `taskdraft-gold-examples.md`。

## 3. 薄稿标签（命中任一 → 建议暂缓）

| 标签 | 含义 |
|------|------|
| `thin_one_liner` | 单行「标题（页面），操作：【…】」 |
| `button_list_only` | 只罗列按钮，无定位/填字段/断言 |
| `no_locate` | 缺进页或缺依赖定位 |
| `menu_nav` | 含 `【…】→【…】` 菜单导航 |
| `produces_placeholder` | produces 为 `…产物` 或与 title 同质 |
| `no_assert` | 无保存成功/列表展示类收尾 |
| `multi_cap_in_chain` | 链上一步写多种写能力（应拆链，勿松闸门） |

反面样例见 `taskdraft-thin-examples.md`。

---

## 4. 与闸门拒绝的分工

| 来源 | 动作 |
|------|------|
| `multi_capability_task_draft` / `multi_persist_task_draft` | 当真阳性：拆 through-chains，勿松闸门 |
| `missing_source_chapter` | 查章节锚点；本 skill 不改 chapters |
| 闸门过但命中 §3 | 质量未达标 → 暂缓 |
| 闸门过且 G1–G5 全过 | 建议勾选 |

杠杆：① 拆链、去菜单导航 → ② 逼多步 taskDraft → ③ 勿再松 cohesion。

---

## 5. `present_pick_list` 必填

每行：`quality` = `near_gold` | `thin`；thin 必填 `flags`；thin 须写未过的 G 条。  
默认只建议勾选 `near_gold`；编排者勾选 thin 时报告写「覆盖质量建议」。
