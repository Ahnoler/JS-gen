# 操作员执行手册（湿测 subagent）

> 来源：`docs/superpowers/reports/2026-09-21-recording-coach-subagent-ops-cases.md` 文首 + `skillWorthy=yes` 卡。  
> 角色：本 skill 是主会话派来的**执行操作员**。规划拆单、自然语言入口不在这里。  
> 粒度速查另见 `phase-granularity.md`（本文不重复合/拆规则）。

`close.txt` 结论前缀仍只允许 `CREATED_` / `REJECTED_` / `BLOCKED_` / `ERROR`。下文的「未裁决」「未核验」「外部故障」一律写成 **`BLOCKED_` 子型**，以便 `write_through_report` 放行。

## 派发缺了就停

主会话任务书至少要有：五段式 brief、**每阶段一个落库判据**、禁区清单、证据目录、以及「主线程独立复核、不采信操作员单方回报」。缺任一项 → 结论 `BLOCKED_派发不完整`，禁止开单。

禁区清单必须包含：**禁删除类探针**（含前端预检 `deleteApply` 一类）。任务书没写的验证一律不做；可疑路径写进回报，不执行（#896）。

复测优先**逐字复用已跑通的任务模板**，只改名单变量、只加本单特化门闩（#971）。不要为了复测重写一套。

## 任务文本可执行（给引擎的 taskText）

1. 提交类操作**点名页面真实按钮文本**（如「保存」）。禁止「保存/确定任一」这类兼容措辞（#904 → #909/#924）。
2. 每阶段预期结果写**落库级判据**（复查编号出现 / 共 0 条），不写「操作成功」。
3. 顺利单的标志是操作员**没有自由发挥空间**：点名按钮 + 落库判据 + 显式残留清单 + 无提交门闩（#924）。

## 结论纪律

| 现象 | 结论 | 禁止 |
|------|------|------|
| 服务端业务拒绝（无有效评级、在途等） | `REJECTED_` + 原文 + 全局流水号 | 改写业务判断；把「摸底说有、服务端说没有」当成操作员可以翻案（#892） |
| 同一确定性拒绝文案第 2 次 | 提前 `REJECTED_` 收口，引用两次原文 | 当暂时失败循环重试、堆流水号（#895/#896）。最多再试 **1** 次 |
| 任务要求裁决/验证 X，但 X 未被观察到 | `BLOCKED_NOT-ADJUDICATED_<断点>`，只写拿到什么、缺什么、断在哪 | 反推「X 不成立 / 另有其他条件」（#910） |
| 「页面没有某按钮」 | 写成「**枚举未见**（index 未分配）」并附当步 inventory | 写成「不存在」并据此改引擎/SUT。定谳升级取证员（Playwright），不靠录制链自证（pdiag） |
| 核验通道当轮已知失灵（树搜索/筛选） | `BLOCKED_UNVERIFIED_<原因>`，待第二通道或 DB 复验 | 据此宣布「未落库 / 已删净」（#902/#903） |
| 同 action 参数级重复 ≥2 轮且当前阶段 done_logs 空 | 立即 detach，`BLOCKED_外部故障_SUT` | 空转到 max_steps。止损逻辑在引擎 D2 守卫，**不要**在 coach 里复制守卫（#925，`engine-side`） |

诚实失败后**禁止再开一单**，除非主会话本回合明确要求重试。

## 管线三条（并入坑位）

1. `phaseIds` = `GET /api/v2/trajectories/:id` 的 `phases[].id`（**数字**）。传 UUID 必 400（#891）。
2. `prepare` / `start_record` 超时 ≥600s。curl 超时后**先 GET 轨迹状态**；已是 recording 则勿再 POST（重复 start 会撞 busy，#971）。
3. 日志：`detach` **前** `GET /api/v2/recording/agent-stderr?trajectoryId=`；detach 后该 API 会空，改为直读引擎 worktree `tmp/executor-main.log`，按 sid 过滤，摘录带行号与时间界（#970/#971）。

## 不要写成铁律

同阶段同名字段拆段规避（#909/#910）对应缺陷已由 `cee623e1` 修复。**勿再写入任务模板**（卡 5，`no-oneoff`）。
